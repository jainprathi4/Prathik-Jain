CSV & capture requirements

Keep training and test data comparable

1
One condition per file

Save each known healthy or fault capture as a separate CSV. Label it from an inspected/known condition.

2
Three-axis acceleration

CSV/TXT/TSV and Excel XLSX/XLS are supported. Prefer columns named Ax, Ay, Az (or Accel_X, Accel_Y, Accel_Z). Excel import reads the first worksheet; a file with three numeric columns is also supported.

3
Keep test setup consistent

Match sensor, mounting point, units, sample rate, engine speed and load wherever possible.

4
Record repeated runs

Take multiple independent recordings for each condition. Do not rely on one sample to represent all faults.

Important: the initial classifier uses simple statistical vibration features and nearest-neighbour similarity. It is a project prototype, not a trained production-grade engine diagnostic model.

Suggested project validation workflow

Separate training evidence from evaluation evidence

✓
Capture known conditions

Healthy, lubrication fault, bearing fault, looseness, and combined faults where available and confirmed.

▤
Repeat each condition

Vary runs deliberately. One CSV upload represents one labelled capture, not a full class by itself.

◉
Hold back test data

Do not evaluate the model only on the recordings used to build its reference dataset.

⚙
Grow beyond this baseline

For the final project, consider FFT/spectral features and a validated classifier, with a confusion matrix and per-class recall.
